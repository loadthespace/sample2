# 제출 전 셀프 점검
항목마다 해당하면 [ ] 안에 체크. 체크 못 한 건 남은 시간 안에 보완하거나 REPORT.md 한계에 적는다.

# ① 기술 관리 (Technique)
결과물이 실제로 돌아가고, 고치기 쉽고, 안전한가
- 코드 유지보수성
    [ ] 판정·계산 코드와 화면 코드가 서로 다른 파일로 나뉘어 있다
    [ ] 같은 코드가 여러 군데 복사돼 있지 않다 (버전별 파일 복사본 없음)
    [ ] 파일 이름과 함수 이름만 봐도 무슨 역할인지 알 수 있다
- 요구사항 충족도
    [ ] AGREEMENT.md의 [필수] 항목이 전부 화면에서 동작한다 (하나씩 직접 눌러 봄)
    [ ] 만들지 않은 항목은 그 이유가 AGREEMENT.md나 REPORT.md에 적혀 있다
- 기능적 정확성
    [ ] 핵심 결과(숫자나 판정) 1~2개를 원본 자료와 직접 대조했다 (VERIFY.md에 기록)
    [ ] 정상 루트가 아닌 반례 입력 10가지 정도를 넣어 봤고, 결과가 기대와 같다
- 실무적 품질 위험
    [ ] API 키 같은 비밀값이 코드와 커밋에 없다
    [ ] 이름 같은 개인정보가 화면이나 파일에 그대로 나오지 않는다 (해당할 때)
    [ ] 빈 입력, 형식 오류, 외부 호출 실패 때 화면에 안내 문구가 나온다
    [ ] 임시 결과나 제외된 데이터가 화면에서 구분돼 보인다
    [ ] 제공받은 원본 자료가 바뀌지 않았다
- 제출물 완성도
    [ ] 서버를 끄고, REPORT.md 실행 방법에 적힌 명령 그대로 새로 켜서 화면이 뜬다
    [ ] 과제가 요구한 파일 이름과 위치대로 제출물이 있다
    [ ] 마지막 변경까지 커밋돼 있다

# ② 의도 관리 (Intent)
AI에게 맡기기 전에 목표를 정했고, 맡긴 뒤에 결과를 통제했는가
- Output 목표 구체화
    [ ] AGREEMENT.md에 성공 기준이 숫자나 확인 방법으로 적혀 있다
    [ ] 프롬프트에 출력 형식(불릿, 표, 파일명 등)을 정해서 시켰다
- 재사용 가능한 작업 체계 구축
    [ ] AGENTS.md를 처음부터 두고, 과제 전용 규칙을 추가했다
    [ ] 같은 검증을 다시 돌릴 수 있게 검증 요청 문장이나 테스트가 남아 있다
- 의도 갱신 및 맥락 유지
    [ ] 담당자에게 새로 들은 조건을 AGREEMENT.md 변경 이력에 적고 커밋했다
    [ ] HANDOFF.md가 버전(v0, v1 ...)마다 추가돼 있다
- 검증 루프 설계 및 통제
    [ ] 구현 세션이 아닌 별도 검증 세션이 REVIEW.md를 썼다
    [ ] REVIEW.md에서 나온 문제를 고친 fix 커밋이 있다 (어떻게 발견했는지 포함)
    [ ] AI가 규칙을 어겼을 때 되돌리거나 바로잡은 기록이 있다 (그런 일이 있었다면)
- 문제 상황 및 제약 정의
    [ ] 담당자 인터뷰를 3번 했다 (처음, v0 직후, 최종 확정 전)
    [ ] AGREEMENT.md에 제약·가드레일과 안 만들 것이 적혀 있다
- 작업 분해·위임 설계
    [ ] /plan으로 단계를 나눴고, 단계마다 범위를 정해서 시켰다
    [ ] 만드는 방법(기술) 후보를 비교해 보고 내가 골랐다 (이유는 DECISIONS.md에)

# ③ 인지 관리 (Cognition)
내가 만든 것을 AI 없이 내 말로 설명할 수 있는가
- AI 산출물 동작 및 리스크 예측
    [ ] 입력이 들어와서 결과가 화면에 나오기까지의 흐름을 말로 설명할 수 있다
    [ ] 어떤 입력이나 상황에서 틀리거나 깨지는지 3가지를 말할 수 있다 (REPORT.md 한계에 적음)
- AI 산출물 구조 이해
    [ ] 핵심 판정 코드를 직접 열어 읽었고, 무슨 뜻인지 모르는 줄이 없다
    [ ] 주요 파일이 각각 무슨 역할인지 말할 수 있다
- AI 의사결정 및 근거 이해
    [ ] 왜 이 기술과 구조를 썼는지, 버린 대안은 무엇인지 말할 수 있다 (DECISIONS.md)
    [ ] AI가 과하게 만든 부분을 찾아서 뺐거나, 남긴 이유를 말할 수 있다
    [ ] BRIEF.md 4번 구현 설명을 보지 않고 내 말로 설명할 수 있다
    [ ] BRIEF.md 5번 질문에 내 답을 써 보고 코드와 비교했다
    [ ] BRIEF.md 4번에 "근거 기록 없음"이 남아 있지 않다 (남았으면 DECISIONS.md에 이유 추가)

# ④ 소통 (Communication)
다른 사람이나 다른 세션이 이어서 작업할 수 있는가
- handoff
    [ ] 새 세션에 HANDOFF.md만 읽혀도 현재 상태를 3줄로 요약할 수 있다
    [ ] 실행 방법이 REPORT.md에 적혀 있다
