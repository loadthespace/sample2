# 내가 해야 할 순서

1. git 템플릿 다운
    git clone https://github.com/loadthespace/sample.git
2. readme 읽기
3. 작업용 폴더를 따로 만들어 templates의 md를 옮겨 환경 구성 후 codex 실행 위치 잡고 on. status 체크 및 model, effort set
    과제 자료(uploads 등) 위치와 최종 제출물을 둘 위치는 과제 안내와 Cofa Helper 답에 맞춘다
4. codex에 README 올리고 문제 구체화 (effort medium)
    ex) 읽고 내가 해야 할 요건, 담당자에게 확인할 것, 우선 합의할 최소 범위를 불릿으로 정리해. 아직 아무것도 만들지 마.
5. codex 답 기다리는 동안 readme 읽으면서 해야겠다 생각 든 질문들 정리
6. 인터뷰 진행 (INTERVIEW.md 참고)
    Cofa Helper: 제출 방식, 필수 파일명 확인
7. 얻은 정보들로 agreement 제작
8. 어떤 단위로 구현할지 플랜/구조화 (PROMPTS.md 참고)
9. 구현
    단계가 끝날 때마다 BRIEF.md 1~2번 확인 (헷갈리면 3번)
    v0 나오면 BRIEF.md 4번 읽고 5번 질문에 답해 보기
10. 검증 (최종 결과물 나올 때까지 9-10 반복)
11. 제출물에 대한 리포트 작성 (요구사항에 있다면)
12. 서술형 답에 대한 생각
    BRIEF.md 4~5번 최종 갱신시키고, 서술형 들어가기 직전에 BRIEF.md 4번과 DECISIONS.md 읽기
13. 결과물 제출


# 제출

제출은 10분 남았을 때 시작


# 제출 직전 = 서술형 설문

제출 후 서술형이므로, 아래 예상 질문과 답변 템플릿을 머릿속에 넣어 놓고 제출

[약점/장애]
    내가 한 것은 ~이다. 약점은 ~이다. 그래서 ~ 상황이 오면 ~이 될 수 있다. 이후에는 ~와 같은 방법으로 확인하고 고치겠다.

[설계 이유]
    ~ 방법을 선택했다. 이번 과제에서 ~라는 상황에서 ~하는 것이 좋다고 생각했다. ~라는 방법도 있었지만 ~라는 이유 때문에 사용하지 않았다. 단, ~와 같은 상황이 생길 경우 지금 이 방식은 문제가 될 수 있으므로, 그때는 ~와 같은 조치가 필요하다.

[아예 전제가 틀린 질문]
    실제로는 ~와 같이 했다. ~했기 때문이다. 그래서 ~와 같이 하지 않았다. ~했으면 ~처럼 될 수 있기 때문이다.

[과정을 설명할 때 쓸 문장]
    문제를 구체화해서 명확한 현재 문제와 해결해야 할 포인트, 그 방법, 조건, 제약 사항, 주의할 점, 예외 등을 파악하기 위해 인터뷰를 충분히 길게 잡았다.
    그리고 바로 이를 기반으로 구현하지 않고, 어떻게 구현하면 좋을지 단계화하고, 플로우를 구상하였다.
